# บันทึกการใช้ AI ช่วยพัฒนา

โจทย์ข้อ 10: "อนุญาตให้ใช้เครื่องมือ AI ช่วยเขียนโค้ดได้เต็มที่ แต่ทีมต้อง
อธิบายโค้ดทุกส่วนที่ส่งได้ และต้องระบุในรายงานว่าใช้ AI ช่วยในส่วนใดบ้าง"

บันทึกทุกครั้งที่ใช้ — ระหว่างทำจะใช้เวลาแค่ 10 วินาที แต่ถ้ารอไปเขียนวันสุดท้ายจะนึกไม่ออก

| วันที่ | ส่วนที่ใช้ AI ช่วย | เครื่องมือ | ใครตรวจทาน | หมายเหตุ |
|---|---|---|---|---|
| 19 ก.ย. 69 | ออกแบบ schema 20 ตาราง (`backend/app/models/`) + migration แรก | Claude Code | _ยังไม่ได้ตรวจทาน_ | โครงสร้างตารางและคำอธิบายเหตุผลในไฟล์ |
| 19 ก.ย. 69 | seed กฎจำแนกประเภท + ค่าธรรมเนียม (`app/seeds/classification.py`) | Claude Code | _ยังไม่ได้ตรวจทาน_ | ค่าตัวเลขมาจากตารางข้อ 4 ของโจทย์ |
| 19 ก.ย. 69 | ชุดทดสอบกฎจำแนก 13 เคส (`backend/tests/`) | Claude Code | _ยังไม่ได้ตรวจทาน_ | ครอบ T-01..T-05 + เคสขอบ |
| 19 ก.ย. 69 | ER Diagram + คำอธิบาย 3NF (`docs/database.md`) | Claude Code | _ยังไม่ได้ตรวจทาน_ | deliverable ข้อ 2 |
| 19 ก.ย. 69 | API เข้าสู่ระบบ + หน้า Login (`api/v1/auth.py`, `(public)/login/`) | Claude Code | _ยังไม่ได้ตรวจทาน_ | M1 บางส่วน |
| 19 ก.ย. 69 | API สมัครสมาชิก + ยืนยัน OTP + หน้า Register | Claude Code | _ยังไม่ได้ตรวจทาน_ | M1 ครบเส้นทาง |
| 19 ก.ย. 69 | ตรวจเลขบัตรประชาชน (`core/thai_id.py`) + เทสต์ 20 เคส | Claude Code | _ยังไม่ได้ตรวจทาน_ | สูตร check digit |

> **ค้างตรวจทาน** — ทั้ง 4 รายการข้างบนยังไม่มีใครในทีมอ่านจนอธิบายได้
> จุดที่ต้องเข้าใจให้ได้ก่อนนำเสนอคือ **ทำไมกฎประเภท 1/2 ถึงไม่กำหนด `min_rooms`**
> (คำตอบอยู่ใน `docs/database.md` หัวข้อ "กับดัก T-02") เพราะเป็นจุดที่กรรมการ
> น่าจะถามตรง ๆ และเป็นเหตุผลเชิงออกแบบ ไม่ใช่แค่โค้ด
>
> จุดที่สองคือ **ทำไมเลขบัตรประชาชนถึงไม่เคยออกไปกับ API** — โจทย์ข้อ 8 ถามตรง ๆ
> ว่าข้อมูลใดต้องจำกัดการเข้าถึงเป็นพิเศษ คำตอบของเราอยู่ในคอมเมนต์ที่
> `backend/app/models/user.py` และ `docs/database.md` หัวข้อ "ข้อมูลส่วนบุคคล"

## สิ่งที่ต้องตอบให้ได้ตอนนำเสนอ

กรรมการมีสิทธิ์ชี้ไปที่โค้ดบรรทัดไหนก็ได้แล้วถามว่าทำงานอย่างไร
ก่อน commit โค้ดที่ AI เขียน ให้คนที่เป็นเจ้าของส่วนนั้นอ่านจนอธิบายได้ก่อน
