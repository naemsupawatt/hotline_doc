# (central) — หน่วยงานส่วนกลาง (role=central)
ภาพรวมทั้งจังหวัด (M11), รายงานเวลารอ/คำขอค้าง (S5), ภาระงานแบบไม่ระบุตัวตน (S6)

ดูได้อย่างเดียว ห้ามมีปุ่มที่แก้ผลพิจารณารายคำขอ

| หน้า | ตอบคำถามอะไร |
|---|---|
| `central/overview` | คำขอทั้งจังหวัดค้างที่ **ขั้นตอน** ใด แยกตามประเภทและท้องถิ่น |
| `central/documents` | ของที่ **ส่งมาแล้ว** ค้างอยู่ที่เอกสารฉบับใด (ลูกบอลอยู่ที่เจ้าหน้าที่) |
| `central/missing-documents` | ของที่ **ยังไม่ถูกส่งมา** ขาดฉบับใดมากที่สุด (ลูกบอลอยู่ที่ผู้ยื่น) |

สองหน้าหลังเป็นคู่แฝดกัน มองคนละฝั่งของกระบวนการ และ **โยงถึงกันด้วยลิงก์บนหน้าจอ**
เพราะถ้าดูหน้าเดียวแล้วเห็นว่าว่าง จะสรุปผิดว่า "เอกสารไม่ติดแล้ว" ทั้งที่อีกฝั่ง
อาจกองอยู่ โครงหน้าจอที่ใช้ร่วมกันอยู่ที่ `components/common/DocumentReport.tsx`
(แถบสรุป + แถวเรียงอันดับ + แท่งเทียบขนาด + ชิปรายเขต) ต่างกันแค่บรรทัดรายละเอียด
ที่ส่งเข้าไปเป็น children **ห้ามแตกเป็นสองชุด** ไม่งั้นวันหนึ่งสองหน้าจะดูคนละระบบ

## เอกสารที่ค้างตรวจ (`central/documents`)

สองหน้านี้ไม่ซ้ำกัน เพราะนำไปสู่การแก้คนละแบบ:

- เอกสารฉบับเดียวค้างแทบทุกเขต → ปัญหาอยู่ที่ **ตัวเอกสารหรือกระบวนการ**
  (แบบฟอร์มกำกวม ขอจากหน่วยงานอื่นยาก) ไม่ใช่ที่เจ้าหน้าที่คนใดคนหนึ่ง
- หลายฉบับค้างกระจุกอยู่เขตเดียว → เขตนั้นกำลังมี **ปัญหากำลังคน**

| เรื่อง | ทำไมเป็นแบบนี้ |
|---|---|
| นับเฉพาะคำขอที่ยังอยู่ในกระบวนการ (`IN_PROCESS`) | เอกสารที่ไม่มีใครตรวจในคำขอที่ตัดสินไปแล้วไม่ใช่คอขวด ไม่มีใครรออยู่ และเจ้าหน้าที่ย้อนกลับไปตรวจไม่ได้แล้ว |
| นับเป็นจำนวน **คำขอ** ที่ติดค้างเอกสารฉบับนั้น | ไม่ใช่จำนวนไฟล์ เพราะฉบับเดียวแนบได้หลาย slot แต่ตรวจกันเป็นฉบับ |
| นิยาม "ยังไม่ได้ตรวจ" | ใช้ `REVIEWED_DOCUMENT_STATUSES` ตัวเดียวกับสัญลักษณ์แจ้งเตือนในคิวเจ้าหน้าที่ **ห้ามนิยามซ้ำที่นี่** ไม่งั้นเจ้าหน้าที่กับส่วนกลางจะเห็นตัวเลขคนละชุดแล้วเถียงกันว่าใครถูก |
| `by_authority[].key` เป็นรหัส อปท. | ไม่ใช่ชื่อ เพราะชื่อแก้ได้จากฐานข้อมูล |
| ยิงคำสั่ง SQL เดียว | ผลลัพธ์มีขนาดเท่ากับ จำนวนเอกสาร x จำนวน อปท. ซึ่งเล็กมาก แล้วจัดกลุ่มในหน่วยความจำ |

**ยังอยู่ใต้กติกาเดิมของหน้าส่วนกลาง** เป็นข้อมูลสรุปล้วน ไม่มีเลขที่คำขอ
ไม่มีชื่อผู้ยื่น ไม่มีชื่อเจ้าหน้าที่ มีเทสต์ `test_document_bottlenecks_keep_the_report_anonymous`
คุมไว้ และเปิดให้เฉพาะ central กับ super_admin เท่านั้น

"ค้างนานสุด" กับ "จำนวน" ตอบคนละคำถาม — ฉบับที่ค้างใบเดียวแต่ค้างมาสามสัปดาห์
ก็ควรถูกมองเห็น จึงแสดงทั้งสองค่าคู่กันทุกแถว

## เอกสารที่ยังไม่ส่ง (`central/missing-documents`)

| เรื่อง | ทำไมเป็นแบบนี้ |
|---|---|
| **รวมคำขอที่ยังเป็นร่าง** (`NOT_DECIDED`) | ต่างจากหน้าคอขวดที่ใช้ `IN_PROCESS` เพราะร่างคือจุดที่ผู้ประกอบการกำลังเตรียมเอกสารและหยุดไปกลางคันมากที่สุด ถ้าตัดร่างออก จะเหลือแต่เอกสารไม่บังคับของคำขอที่ยื่นแล้ว (M6 บังคับให้เอกสารบังคับครบก่อนยื่น) ซึ่งแทบไม่บอกอะไร |
| **แยกยอด "บังคับ" ออกมาเสมอ** | เอกสารไม่บังคับบางฉบับตั้งใจให้ขาดได้ — ช่องแนบใน ร.ร.1 เช่นหนังสือรับรองนิติบุคคล ซึ่งบุคคลธรรมดาไม่มีอยู่แล้ว ถ้ารวมเป็นตัวเลขเดียว ยอดจะพองด้วยของที่ไม่มีใครต้องส่ง แล้วอ่านผิดว่าผู้ยื่นทิ้งงาน |
| **รายการเอกสารที่ต้องใช้ ยึด snapshot ผลจำแนกของคำขอ** | ใช้กติกาเดียวกับ `classification.required_documents` คือดูจาก `document_requirement` ของประเภทนั้น และนับเฉพาะ `document_type` ที่ยังเปิดใช้งาน ถ้าสองที่นี้หลุดจากกัน ตัวเลขของส่วนกลางจะไม่ตรงกับที่ผู้ยื่นเห็นบนหน้าจอตัวเอง |
| คำขอที่ตัดสินแล้วไม่นับ | ไม่มีใครต้องส่งอะไรเพิ่มอีก |
