# (operator) — ผู้ประกอบการ

URL ขึ้นต้นด้วย `/operator/...` เสมอ (ตรงกับ `homeFor()` ใน `lib/auth.ts`)
โฟลเดอร์ `(operator)` เป็น route group ไว้จัดกลุ่มตามบทบาท ไม่ได้เพิ่ม segment
ให้ URL จึงต้องมีโฟลเดอร์ `operator/` อยู่ข้างในอีกชั้น

| หน้า | โจทย์ข้อ | สถานะ |
|---|---|---|
| `operator/wizard` ประเมินที่พัก + รายการเอกสาร + เริ่มยื่นคำขอ | M2 M3 M4 | ใช้งานได้ |
| `operator/applications/[no]` รายละเอียด + อัปโหลด + ยื่น | M5 M6 M7 | ใช้งานได้ |
| `operator/applications/[no]/forms/[code]` แบบฟอร์ม A01/A06 + ลายมือชื่อ + พิมพ์ PDF | M3 M5 | ใช้งานได้ |
| ผู้ช่วยตอบคำถาม (ปุ่มลอยทุกหน้าในกลุ่มนี้) | — | ใช้งานได้ |
| เอกสารของฉัน + อัปโหลด | M5 | ยังไม่เริ่ม |
| ยื่นคำขอ | M6 | ยังไม่เริ่ม |
| ติดตามสถานะ | M7 | ยังไม่เริ่ม |
| พิมพ์ใบอนุญาต | M10 | ยังไม่เริ่ม |

หน้า wizard เปิดได้โดยไม่ต้องล็อกอิน ตั้งใจตาม US-01 ให้ลองประเมินก่อนสมัคร

## แถบความคืบหน้าในหน้า "คำขอของฉัน" (M7)

ทุกแถวมีแถบ 4 ขั้น: จัดเตรียมเอกสาร → ยื่นคำขอ → เจ้าหน้าที่ตรวจสอบ → ออกเอกสารสิทธิ์
พร้อมป้ายบอกว่า "ลูกบอลอยู่ในมือใคร" แบบเดียวกับแท็บคิวของเจ้าหน้าที่
แต่มองจากฝั่งผู้ยื่น และจำนวนวันที่ค้างอยู่ในขั้นปัจจุบัน

| สถานะ | ขั้นที่ | ใครต้องลงมือ |
|---|---|---|
| draft | 1 จัดเตรียมเอกสาร | ผู้ยื่น |
| submitted | 2 ยื่นคำขอ | เจ้าหน้าที่ |
| under_review | 3 เจ้าหน้าที่ตรวจสอบ | เจ้าหน้าที่ |
| needs_revision | 3 เจ้าหน้าที่ตรวจสอบ | **ผู้ยื่น** (แถบเปลี่ยนเป็นสีส้ม) |
| approved | 4 ออกเอกสารสิทธิ์ | เจ้าหน้าที่ (ยังต้องกดออกใบอนุญาต M10) |
| license_issued | ครบทุกขั้น | — |
| rejected | หยุดที่ขั้น 3 | — (แถบไม่เดินต่อ) |

ตารางนี้อยู่ในโค้ดที่ `lib/progress.ts` ที่เดียว (`Record<ApplicationStatus, ...>`
บังคับให้ครบทุกสถานะเสมอ) ส่วน `ProgressTrack.tsx` รู้แค่วิธีวาด
เหตุผลที่ไม่ใช้ `Stepper.tsx`: อันนั้นเป็นวงกลม 4 วงพร้อมป้าย เหมาะกับหน้าเดี่ยว
ไม่ใช่รายการที่มีหลายสิบแถว

`days_waiting` นับจาก `status_changed_at` ไม่ใช่วันที่สร้างคำขอ ข้อความจึงเป็น
"อยู่ในขั้นนี้ X วัน" ไม่ใช่ "ยื่นมาแล้ว X วัน"

## แบบฟอร์มที่ระบบกรอกให้ (A01 หนังสือแจ้งฯ / A06 ร.ร.1)

`operator/applications/[no]/forms/[code]` เป็นทั้งหน้าจอและต้นฉบับกระดาษในตัวเดียวกัน
ระบบกรอกทุกช่องจากข้อมูลคำขอ เหลือช่องเดียวที่ระบบทำแทนไม่ได้คือลายมือชื่อผู้ยื่น
ปุ่ม "พิมพ์ / บันทึกเป็น PDF" ใช้การพิมพ์ของเบราว์เซอร์ (ดู `docs/decisions.md` ข้อ 12)
สิ่งที่ไม่ควรติดไปกับกระดาษใส่คลาส `print:hidden`

| | A01 หนังสือแจ้งฯ | A06 แบบ ร.ร.1 |
|---|---|---|
| ใช้กับ | ไม่เข้าข่ายโรงแรม | ประเภทที่ 1 และ 2 |
| ผู้ลงชื่อ | ผู้แจ้ง | ผู้ขออนุญาต |
| มีค่าธรรมเนียมบนกระดาษ | ไม่มี | มี |
| ช่องติ๊กเอกสารแนบ | ไม่มี | A07–A09 (ระบบติ๊กให้จากไฟล์ที่แนบแล้ว) |

**เส้นทางเดียว โครงเดียว** — ทั้งสองฉบับใช้ `SystemFormPaper.tsx` ร่วมกัน
(โหลดข้อมูล ปุ่มพิมพ์ หัวกระดาษ ช่องลงชื่อ แผงแก้ชื่อผู้ยื่น แผงลงลายมือชื่อ)
`components/common/SystemFormView.tsx` มีแต่เนื้อความของแต่ละฉบับ
เปิดรหัสที่ไม่มีจะได้หน้าบอกว่าไม่มีแบบฟอร์มนั้น
ส่วนเปิดแบบฟอร์มผิดประเภท (เช่น A06 ของคำขอที่ไม่เข้าข่ายโรงแรม) API ตอบ 404
พร้อมบอกว่าเป็นเพราะประเภทที่พัก

ลายมือชื่อวาดบนจอหรืออัปโหลดรูปก็ได้ ทั้งสองทางออกมาเป็น PNG พื้นหลังโปร่ง
แล้วส่งเข้าช่องอัปโหลดของเอกสารฉบับนั้นตรง ๆ (ไม่มี endpoint ใหม่) จึงได้ระบบรุ่น
การตรวจของเจ้าหน้าที่ และการล็อกหลังยื่นคำขอ มาโดยไม่ต้องเขียนเพิ่ม

**ลายมือชื่อเป็นเอกสารบังคับ** ยื่นคำขอไม่ได้จนกว่าจะเซ็น (ดู `docs/decisions.md` ข้อ 12)
ถ้าถนัดเซ็นบนกระดาษ ให้พิมพ์แบบฟอร์มออกไปเซ็นแล้วถ่ายรูปมาอัปโหลด

**หน้าคำขอไม่แสดง `ลายมือชื่อ.png` เป็นรายการไฟล์** ของเอกสารสองฉบับนี้
เพราะไฟล์นั้นเป็นแค่รูปลายเซ็น ไม่ใช่ตัวเอกสาร คนอ่านจะเข้าใจว่าสิ่งที่ส่งไปคือรูป
จึงเหลือปุ่มเดียวที่พาไปหนังสือทั้งใบ ไฟล์ยังถูกเก็บเป็นรุ่นเหมือนเดิมทุกอย่าง
เจ้าหน้าที่ก็เห็นกระดาษใบเดียวกันนี้ที่ `/officer/applications/[no]/forms/[code]`
(ดู `docs/decisions.md` ข้อ 16)

**ชื่อผู้ยื่นบนแบบฟอร์มแก้ได้จากหน้านี้** เพราะแบบ ร.ร.1 มีช่องบุคคลธรรมดา/นิติบุคคล
ซึ่งตอนสมัครยังไม่ได้ถาม แก้แล้วมีผลกับคำขอใบอื่นของคนเดียวกันด้วย ตั้งใจให้เป็นแบบนั้น
เพราะเป็นตัวตนของผู้ประกอบการ ไม่ใช่ข้อมูลเฉพาะคำขอใบใดใบหนึ่ง

หน้าใบอนุญาต (`license/`) มีช่องลงนามของเจ้าหน้าที่ผู้ออกเอกสารด้วย
ลายมือชื่อนั้นเจ้าหน้าที่เซ็นตอนกดออกเอกสาร (ดู `docs/decisions.md` ข้อ 13)

## ผู้ช่วยตอบคำถาม (แชทบอท)

อยู่ที่ `layout.tsx` ของกลุ่มนี้ ไม่ใช่รายหน้า เพราะคำถามมักเกิดตอนทำอย่างอื่น
ค้างอยู่ และประวัติการคุยจะไม่หายเมื่อเปลี่ยนหน้าในกลุ่มเดียวกัน

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/chatbot.ts` | คลังคำถาม-คำตอบทั้งหมด + การจับคำสำคัญ |
| `components/common/ChatAssistant.tsx` | วิธีคุยเท่านั้น ไม่รู้เนื้อหาคำตอบ |

แก้ข้อความหรือเพิ่มคำถามใหม่ ทำที่ `lib/chatbot.ts` ที่เดียว ไม่ต้องแตะหน้าจอ

**ยังไม่ต่อ AI โดยตั้งใจ** (ดู `docs/decisions.md` ข้อ 14) เป็นชุดคำถามที่เตรียมไว้
บวกการนับคำสำคัญจากข้อความที่พิมพ์เข้ามา ถ้าจับคำไม่ได้จะบอกตรง ๆ ว่าตอบไม่ได้
แล้วเสนอหัวข้อให้เลือก **ไม่เดาคำตอบ**

**คำตอบที่เป็นกฎเกณฑ์ดึงจาก API จริงเสมอ** เช่น ถาม "ต้องเตรียมเอกสารอะไรบ้าง"
บอทจะถามจำนวนห้อง/จำนวนคน/ห้องอาหาร แล้วยิง `/wizard/classify` จริง
ไม่ได้เก็บเกณฑ์หรือรายการเอกสารไว้ในตัวเอง ห้ามเขียนตัวเลขกฎลงในคำตอบเด็ดขาด
