# (officer) — เจ้าหน้าที่ท้องถิ่น (role=officer)

URL ขึ้นต้นด้วย `/officer/...` เสมอ (ตรงกับ `homeFor()` ใน `lib/auth.ts`)

| หน้า | โจทย์ข้อ | สถานะ |
|---|---|---|
| `officer/queue` คิวคำขอในเขตของตน | M8 | ใช้งานได้ |
| `officer/applications/[no]` ตรวจเอกสาร + สรุปผล | M8 M9 | ใช้งานได้ |
| คลังกรณีศึกษา | S2 | ยังไม่เริ่ม |

## คิวคำขอแบ่งเป็น 4 แท็บตามว่า "ลูกบอลอยู่ในมือใคร"

| แท็บ | สถานะที่รวม | ความหมาย |
|---|---|---|
| รอฉันดำเนินการ | submitted, under_review, **approved** | ต้องลงมือเอง |
| รอผู้ยื่นแก้ไข | needs_revision | ทำอะไรไม่ได้จนกว่าผู้ยื่นจะส่งกลับ |
| จบแล้ว | license_issued, rejected | ประวัติ |
| ทั้งหมด | ทุกสถานะยกเว้น draft | |

**`approved` ต้องอยู่ในแท็บแรก** เพราะยังค้างการออกเอกสาร (M10)
ถ้าเอาออก คำขอจะหายจากคิวทันทีที่กดอนุมัติ แล้วกดออกใบอนุญาตไม่ได้อีกเลย

ไม่มีช่องกรองสถานะในหน้านี้ เพราะแท็บทำหน้าที่นั้นแล้ว การมีทั้งสองอย่าง
กลายเป็นตัวกรองสองชั้นคนละระดับ (แท็บเลือกว่าโหลดอะไร ช่องกรองกรองสิ่งที่โหลดมา)

**ทุกหน้าในกลุ่มนี้ต้องกรองด้วย อปท. ของผู้ใช้เสมอ — ดู T-09**
การกรองทำที่ฝั่งเซิร์ฟเวอร์ (`services/officer.py`) หน้าจอไม่ได้กรองเอง
คำขอนอกเขตจึงเปิดไม่ได้แม้จะพิมพ์ URL ตรง ๆ และความพยายามนั้นถูกบันทึกไว้

## ออกเอกสารต้องลงนามเสมอ (M10)

ปุ่ม "ออกใบอนุญาต" เปลี่ยนเป็นช่องลงลายมือชื่อ + ปุ่ม "ลงนามและออกเอกสาร"
เพราะเอกสารที่ไม่มีใครลงนามคือเอกสารที่ใช้ไม่ได้ และถ้าแยกเป็นสองขั้นจะเกิด
สถานะกลางที่เอกสารออกไปแล้วแต่ยังไม่มีใครลงนาม ซึ่งไม่ควรมีอยู่จริง
ลายมือชื่อไปปรากฏบนกระดาษที่ผู้ยื่นพิมพ์ออกไป (ดู `docs/decisions.md` ข้อ 13)

ลายมือชื่อของผู้ยื่นในแบบฟอร์ม A01/A06 เป็นไฟล์แนบปกติ เจ้าหน้าที่จึงตรวจ
ผ่าน/ขอให้แก้ไขได้เหมือนเอกสารฉบับอื่น และต้องผ่านก่อนจึงจะอนุมัติได้
