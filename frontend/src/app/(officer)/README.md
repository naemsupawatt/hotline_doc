# (officer) — เจ้าหน้าที่ท้องถิ่น (role=officer)

URL ขึ้นต้นด้วย `/officer/...` เสมอ (ตรงกับ `homeFor()` ใน `lib/auth.ts`)

| หน้า | โจทย์ข้อ | สถานะ |
|---|---|---|
| `officer/queue` คิวคำขอในเขตของตน | M8 | ใช้งานได้ |
| `officer/applications/[no]` ตรวจเอกสาร + สรุปผล | M8 M9 | ใช้งานได้ |
| คลังกรณีศึกษา | S2 | ยังไม่เริ่ม |

## คิวคำขอแบ่งเป็น 4 แท็บตามว่า "ลูกบอลอยู่ในมือใคร"

| แท็บ | สถานะที่รวม | ความหมาย |
|---|---|---|
| รอฉันดำเนินการ | submitted, under_review, **approved** | ต้องลงมือเอง |
| รอผู้ยื่นแก้ไข | needs_revision | ทำอะไรไม่ได้จนกว่าผู้ยื่นจะส่งกลับ |
| จบแล้ว | license_issued, rejected | ประวัติ |
| ทั้งหมด | ทุกสถานะยกเว้น draft | |

**`approved` ต้องอยู่ในแท็บแรก** เพราะยังค้างการออกเอกสาร (M10)
ถ้าเอาออก คำขอจะหายจากคิวทันทีที่กดอนุมัติ แล้วกดออกใบอนุญาตไม่ได้อีกเลย

ไม่มีช่องกรองสถานะในหน้านี้ เพราะแท็บทำหน้าที่นั้นแล้ว การมีทั้งสองอย่าง
กลายเป็นตัวกรองสองชั้นคนละระดับ (แท็บเลือกว่าโหลดอะไร ช่องกรองกรองสิ่งที่โหลดมา)

**ทุกหน้าในกลุ่มนี้ต้องกรองด้วย อปท. ของผู้ใช้เสมอ — ดู T-09**
การกรองทำที่ฝั่งเซิร์ฟเวอร์ (`services/officer.py`) หน้าจอไม่ได้กรองเอง
คำขอนอกเขตจึงเปิดไม่ได้แม้จะพิมพ์ URL ตรง ๆ และความพยายามนั้นถูกบันทึกไว้

## ออกเอกสารต้องลงนามเสมอ (M10)

ปุ่ม "ออกใบอนุญาต" เปลี่ยนเป็นช่องลงลายมือชื่อ + ปุ่ม "ลงนามและออกเอกสาร"
เพราะเอกสารที่ไม่มีใครลงนามคือเอกสารที่ใช้ไม่ได้ และถ้าแยกเป็นสองขั้นจะเกิด
สถานะกลางที่เอกสารออกไปแล้วแต่ยังไม่มีใครลงนาม ซึ่งไม่ควรมีอยู่จริง
ลายมือชื่อไปปรากฏบนกระดาษที่ผู้ยื่นพิมพ์ออกไป (ดู `docs/decisions.md` ข้อ 13)

ลายมือชื่อของผู้ยื่นในแบบฟอร์ม A01/A06 เป็นไฟล์แนบปกติ เจ้าหน้าที่จึงตรวจ
ผ่าน/ขอให้แก้ไขได้เหมือนเอกสารฉบับอื่น และต้องผ่านก่อนจึงจะอนุมัติได้

## ทุกการตัดสินส่งอีเมลถึงผู้ยื่นอัตโนมัติ

ขอให้แก้ไข / อนุมัติ / ไม่อนุมัติ / ออกเอกสาร — ระบบส่งอีเมลไปยังที่อยู่ที่ผู้ยื่น
ใช้สมัครสมาชิก พร้อมเหตุผลที่เจ้าหน้าที่กรอกและลิงก์กลับเข้าระบบ
(ดู `docs/decisions.md` ข้อ 15 และ `backend/app/services/notification.py`)

เจ้าหน้าที่จึงควรกรอกเหตุผลให้ผู้ยื่นอ่านรู้เรื่อง เพราะข้อความนั้นถูกส่งออกไปตรง ๆ

ตอนพัฒนา/สาธิต อีเมลถูกเขียนเป็นไฟล์ไว้ที่ `backend/storage/outbox/` แทนการส่งจริง
เปลี่ยนเป็นส่งจริงได้ด้วย `EMAIL_BACKEND=smtp` ใน `.env`

## แบบฟอร์มที่ระบบกรอกให้ — เจ้าหน้าที่ต้องเห็นตัวหนังสือ ไม่ใช่แค่รูปลายเซ็น

ไฟล์แนบของ A01 (หนังสือแจ้งฯ) และ A06 (ร.ร.1) คือ **รูปลายมือชื่อเพียงอย่างเดียว**
เปิดไฟล์นั้นดูแล้วบอกไม่ได้เลยว่าเซ็นกำกับข้อความอะไรไว้ ทั้งที่เจ้าหน้าที่คือคน
ที่ต้องตัดสินว่าเอกสารฉบับนั้นผ่านหรือไม่ผ่าน

`/officer/applications/[no]/forms/[code]` จึงแสดงกระดาษทั้งใบพร้อมลายมือชื่อ
ฉบับเดียวกับที่ผู้ยื่นเห็น — ใช้คอมโพเนนต์ร่วมกัน (`components/common/SystemFormView.tsx`
ส่ง `viewer="officer"`) และฝั่งเซิร์ฟเวอร์ใช้ presenter ตัวเดียวกัน
(`presenters.to_system_form_out`) ถ้าทำแยกกันสองชุด วันหนึ่งสองฝั่งจะเห็นคนละฉบับ

มุมมองเจ้าหน้าที่เป็นแบบอ่านอย่างเดียวเสมอ ไม่มีแผงลงลายมือชื่อและแก้ชื่อผู้ยื่น
เพราะลายมือชื่อเป็นของผู้ยื่น การผ่าน/ไม่ผ่านยังทำที่หน้าคำขอเหมือนเดิม
endpoint ใช้ guard ตัวเดียวกับหน้าอื่น คำขอนอกเขตจึงเปิดไม่ได้และถูกบันทึกไว้ (T-09)

## เอกสารที่ออกให้ — คนลงนามต้องเปิดดูได้

`/officer/applications/[no]/license` แสดงใบอนุญาต/หนังสือรับรองใบเดียวกับที่ผู้ยื่นเห็น
เปิดได้จากปุ่มในกล่อง "ออกเอกสารแล้ว" บนหน้าคำขอ และมีปุ่มพิมพ์ / บันทึกเป็น PDF ในตัว

เดิมหลังกดลงนามออกเอกสาร เจ้าหน้าที่เห็นแค่เลขที่เอกสาร ทั้งที่เป็นคนลงนามเอง
และเป็นคนที่ผู้ยื่นจะโทรมาถามเมื่อข้อความบนเอกสารผิด

ใช้คอมโพเนนต์เดียวกับฝั่งผู้ยื่น (`components/common/LicenseView.tsx` ส่ง `viewer="officer"`)
และ presenter เดียวกัน (`presenters.to_license_out_for`) มีเทสต์
`test_officer_and_operator_see_the_same_document` เทียบ response สองเส้นทางให้เท่ากันทุกฟิลด์
guard เป็นตัวเดียวกับหน้าอื่น เอกสารของคำขอนอกเขตจึงเปิดไม่ได้ (T-09)
