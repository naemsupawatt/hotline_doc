# บัญชีของฉัน — ใช้ร่วมทุกบทบาท

| หน้า | ตอบข้อใด | สถานะ |
|---|---|---|
| `/account` ดู/แก้ข้อมูลบัญชี + เปลี่ยนรหัสผ่าน | M1 (บัญชีผู้ใช้) | ใช้งานได้ |

อยู่เป็นกลุ่มของตัวเองเพราะทุกบทบาทใช้หน้าเดียวกัน ถ้าไปวางไว้ใต้ `(operator)`
เจ้าหน้าที่กับส่วนกลางจะเข้าไม่ถึง และถ้าทำสี่หน้าแยกตามบทบาทก็จะต้องแก้สี่ที่ทุกครั้ง

## แก้อะไรได้บ้าง และทำไมบางอย่างแก้ไม่ได้

| ช่อง | แก้ได้ | เหตุผล |
|---|---|---|
| ชื่อ–นามสกุล | ได้ | คนกรอกผิดตอนสมัครต้องแก้เองได้ ไม่ใช่ต้องขอให้ไปแก้ในฐานข้อมูล |
| อีเมล / เบอร์โทรศัพท์ | ได้ | เป็นกุญแจเข้าสู่ระบบทั้งคู่ (M1) แก้แล้วใช้เข้าระบบได้ทันที ระบบกันซ้ำกับบัญชีอื่นแบบเดียวกับตอนสมัคร |
| รหัสผ่าน | ได้ (ต้องกรอกรหัสเดิม) | กันคนที่ได้โทเคนไปยึดบัญชีโดยไม่รู้รหัสเดิม |
| เลขประจำตัวประชาชน | **ไม่ได้** | หนึ่งเลขบัตรต่อหนึ่งบัญชีคือกลไกกันบัญชีขยะที่เหลืออยู่หลังทีมตัดสินใจไม่ทำ OTP |
| บทบาท | **ไม่ได้** | ถ้าเจ้าของบัญชีเปลี่ยนเองได้ ใครก็เลื่อนตัวเองเป็นเจ้าหน้าที่ได้ |
| ชื่อผู้ยื่นบนแบบฟอร์ม (ผู้ประกอบการ) | ไม่ได้ที่หน้านี้ | เป็นคนละอย่างกับชื่อเจ้าของบัญชี และล็อกหลังยื่นคำขอแล้ว จึงแก้ที่หน้าแบบฟอร์มของคำขอนั้น |

ทุกการแก้ถูกบันทึกลง AuditLog (`profile.update` / `password.change`) รวมถึงกรณี
กรอกรหัสเดิมผิด ซึ่งเป็น "ความพยายามเข้าถึง" แบบเดียวกับการล็อกอินไม่สำเร็จและ T-09
